## Basic

### 1. What is the difference between a Local User Account and a Domain User Account?

**Answer:**
- **Local User Account:** Stored in the local Security Account Manager (SAM) database of an individual machine. The account can only authenticate and access resources on that specific local computer.
- **Domain User Account:** Stored centrally in Active Directory Domain Services (`NTDS.dit`) on the Domain Controller. The account can authenticate from any domain-joined workstation across the network and access centralized domain resources.

### 2. What is a Security Identifier (SID) in Windows?

**Answer:**
A Security Identifier (SID) is a globally unique alphanumeric string (e.g., `S-1-5-21-...-1002`) generated by Windows when a user, group, or computer account is created. Windows evaluates access permissions by matching SIDs in the user's access token against SIDs in an object's Access Control List (ACL), not by username. Renaming an account does not change its SID.

### 3. What is an Organizational Unit (OU) in Active Directory?

**Answer:**
An Organizational Unit (OU) is a container object within an Active Directory domain used to organize users, groups, and computers into logical structures (such as departments or branch offices). OUs are the smallest administrative boundary to which Group Policy Objects (GPOs) can be linked and administrative permissions can be delegated.

## Intermediate

### 4. Why should administrators assign file and resource permissions to Security Groups rather than individual users?

**Answer:**
Assigning permissions directly to individual users is inefficient, prone to human error, and creates permission sprawl that is impossible to audit at scale. By assigning permissions to **Security Groups** (e.g., `SOC-Analysts`, `SOC-Managers`), access control is managed entirely by updating group memberships in Active Directory without touching file server ACLs when personnel change roles.

### 5. Why do enterprise administrators disable employee accounts upon offboarding rather than immediately deleting them?

**Answer:**
1. **Preserves Audit History:** Deleting an account destroys its unique SID forever. If deleted, historical event logs and file ownership records display unresolvable orphaned SIDs (`S-1-5-...`) rather than user identities.
2. **Access Revocation:** Disabling immediately terminates authentication across the entire domain without breaking data ownership.
3. **Data Transition:** Disabling allows IT teams time to reassign mailbox data, OneDrive storage, and file ownership before permanent decommissioning.

## Scenario-Based

### 6. A SOC analyst observes Windows Security Event ID 4728 followed immediately by Event ID 4672. What occurred, and why is this critical?

**Answer:**
- **Event ID 4728:** "A member was added to a security-enabled global group."
- **Event ID 4672:** "Special privileges assigned to new logon" (administrative logon).
- **Analysis:** This indicates that an account was added to a privileged security group (e.g., Domain Admins or SOC-Admins) and immediately used to authenticate with elevated rights. This is a classic indicator of compromise (IoC) representing attacker privilege escalation or backdoor persistence (MITRE ATT&CK T1098). The analyst must immediately verify authorization.
